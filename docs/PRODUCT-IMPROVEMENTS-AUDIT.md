## Confirmed change implemented in this update

The user explicitly confirmed premium detailed analytics should be **included in both Starter and Growth**. Active Growth trials receive the same access. This supersedes the old separate NGN 5,000 report charge.

- Removed report checkout from the page and checkout API; migration **012_included_analytics.sql** disables new analytics orders in the database catalog.
- Existing orders, previously purchased reports and their billing history remain intact. Existing gateway checkouts may still settle through the existing verified-payment handling; this migration does not cancel an already issued provider checkout.
- Owners/managers of active businesses can prepare 7-, 30- or 90-day reports. Each business gets one immutable snapshot per selected period per Lagos day, shared across its members; repeat requests return that snapshot. Failed preparation can retry after five minutes. Sync before the first preparation of the day. This bounds provider use without charging per report.
- Detailed reports include revenue, recorded cost, gross profit/margin, average sale, cash collected, customer credit, inventory capital, product performance, stock-cover estimates, payment mix, balance age, daily results, and prioritised record-based actions. CSV includes the action plan and limitations.
- Optional AI explains the same aggregate facts. Numerical analysis and practical recommendations remain available without an AI provider. No promised profits, invented due dates or historical discount guesses.
- Existing account roles remain: owners/managers prepare; workspace members can read available reports. Included reports require active access. Previously purchased reports remain readable by members after expiry/pause.

Apply migration 012 once in Supabase after 001–011, then deploy this code. Earlier migrations should not be rerun. The read-only migration checker includes 012. The update does not itself apply changes to the hosted database.

## Implementation order for the remaining document

1. **Financial foundation first:** original/agreed line prices, explicit discounts, recorder identity and due dates; backend invariants; additive migration; safe legacy defaults. Include sale creation, import, offline replay, backups and reconciliation. Preserve old records and distinguish unknown historical discounts from zero verified discounts.
2. **All financial surfaces together:** receipts/payment status, stock-default preservation, customer debt, dashboards, discount card/breakdown, daily/weekly/monthly reporting and exports. Verify document scenarios A, B and C end to end.
3. **Receipt refinements:** business/reference/date filenames and an optional standard-page centred PDF mode alongside existing narrow downloads. Render and inspect complete short/long receipts on mobile/desktop.
4. **Extend existing Web Push:** independently selectable low-stock, overdue and report categories; durable threshold rearm and overdue-event identities; scheduler-backed report generation; secure delivery; correct report deep links. Test invalid endpoints, retries, deduplication, pause/expiry and multiple devices.
5. **Physical-device acceptance:** supported Android and installed iOS PWA, foreground/background/closed app, permission denial and revocation. Browser mocks cannot substitute for actual operating-system delivery.

The remaining items above are findings and proposed work, not claims that these features have already been implemented by this analytics update.
